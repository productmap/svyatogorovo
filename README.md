# Святогорово — лендинг

Одностраничный лендинг паломнического и семейного туристического центра в деревне Святогорово (Дмитровский район, Московская область). Канонический адрес: <https://святогорово.рф/>.

Стек: **Vite + ванильный JS (ES-модули) + SCSS**, без фреймворков. Весь контент живёт в `index.html`. Подробнее об архитектуре — в [`CLAUDE.md`](CLAUDE.md), о SEO-стратегии — в [`docs/strategy.md`](docs/strategy.md).

## Установка

```bash
npm install
```

Нужен Node.js 20+ (требование Vite 8).

## Разработка

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер Vite на `0.0.0.0:3078` (доступен и в локальной сети) |
| `npm run build` | Прод-сборка в `dist/` (перед сборкой обновляет sitemap) |
| `npm run preview` | Локально отдаёт уже собранный `dist/` |

## Деплой

```bash
npm run deploy
```

Собирает проект (`predeploy` → `vite build`) и публикует содержимое `dist/` на GitHub Pages командой `gh-pages -d dist` (ветка `gh-pages` репозитория `svyatogorovo/page`). Прод отдаётся на <https://святогорово.рф/>.

Коммитить или пушить отдельно для деплоя не нужно — `gh-pages` сам пушит `dist/`.

## Скрипты (`scripts/`)

Запускаются вручную через `node scripts/<имя>.js`. Исключение — `update-sitemap.js`, он вызывается автоматически перед сборкой.

### Картинки

- **`gen-webp.js`** — генерирует/обновляет `.webp` для каждого `.jpg` в `public/images/`. Пересоздаёт webp, если jpg новее webp (или webp ещё нет); существующую пару всегда перезаписывает на месте; не создаёт новую пару, если webp получился бы не меньше jpg.
- **`sync-img-dims.js`** — проставляет в `index.html` реальные `width`/`height` для каждого `<img src="/images/…">` по факту с диска. Нужен после кропа/замены картинки: по этим атрибутам браузер резервирует место (нет скачков вёрстки, лучше CLS), а галерея PhotoSwipe берёт из них соотношение сторон.
- **`wrap-img-webp.js`** — оборачивает «голые» `<img src="…jpg">` в `<picture>` с `<source …webp>`, чтобы браузеры с поддержкой webp брали меньший файл. Идемпотентный: пропускает уже обёрнутые и картинки без webp-соседа на диске.

#### Рабочий процесс после правки картинки

Обрезал/заменил фото в `public/images/` — прогони:

```bash
node scripts/gen-webp.js        # обновить webp под новый jpg
node scripts/sync-img-dims.js   # подтянуть width/height в разметке
node scripts/wrap-img-webp.js   # обернуть в <picture> (для новых фото)
```

Затем `npm run build` / `npm run preview`. На сборке `ViteImageOptimizer` ещё раз пережимает все картинки в quality 75 для доставки — поэтому размер исходных файлов влияет в основном на вес репозитория, а доставляемые всегда оптимизированы.

> Если у какого-то фото webp по факту **больше** jpg (бывает с «шумными» снимками — сравни размеры в `dist/images/`), его лучше отдавать как jpg: удалить `public/images/<имя>.webp` и вернуть `<img>` к «голому» виду без `<picture>`/`<source>`. После этого `gen-webp`/`wrap-img-webp` его не тронут.

### Бренд и иконки

- **`gen-logo-svg.js`** — перегенерирует SVG-логотипы из шрифта VezitsaCyrillic (вытаскивает глиф «С» как `<path>`): `public/icons/favicon.svg` и `favicon-maskable.svg`.
- **`gen-icons.js`** — растрирует эти SVG в PNG/ICO: `icon-192/512.png`, `icon-maskable.png`, `apple-touch-icon.png`, `favicon.ico`. Запускать после `gen-logo-svg.js`.

### Прочее

- **`update-sitemap.js`** — ставит сегодняшнюю дату в `<lastmod>` в `public/sitemap.xml`. Вызывается автоматически как `prebuild`, вручную обычно не нужен.
- **`gen-topo.js`** — заново тянет сетку высот рельефа из OpenTopoData и перезаписывает `src/topo-data.js` (анимированный фон с контурными линиями). Запускать только если намеренно обновляешь рельеф; файл авто-генерируемый, руками не править.

## Заметки о сборке

`vite.config.js`, помимо стандартного Vite:

- **`ViteImageOptimizer`** — пережимает `jpg/jpeg/webp/png` в quality 75.
- **`inlineCssPlugin`** — инлайнит собранный CSS в `<style>` внутри HTML (убирает рендер-блокирующий стиль ради Lighthouse).
- **`inlineSvgPlugin`** — заменяет `<img src="/images/*.svg">` на инлайновый `<svg>`. Из-за этого иконкам-`<img>` из SVG нельзя задавать вид через селектор `img` — он перестанет совпадать; цвет задавай через `currentColor`/класс на самом `<svg>`.

Тестов, линтера и форматтера в проекте нет.
